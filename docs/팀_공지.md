# 팀원 공지

## 개발 일정 (중요)
- **개발 완료 기한은 일요일 밤 6시**입니다. 이 시간까지 맡은 TODO를 끝내고 PR을 보내 주세요.
- 늦어도 **월요일까지는 반드시 마무리**해야 합니다. 월요일을 넘기지 않도록 일요일 전에 막히는 부분은 바로 SEONGHO에게 알려 주세요.
- PR은 작게 자주 보내야 리뷰와 머지가 밀리지 않습니다. 기한 직전에 몰아서 보내지 마세요.

## 먼저 읽을 것
1. `AGENTS.md` — 프로젝트 규칙, 실행·테스트 명령, 더미 상태, 제품 규칙, Git 규칙
2. `docs/todo/TODO_본인이름.md` — 내가 맡은 일 (성호·재현·수용·서준·석원)
3. `docs/TODO_충돌_오류.md` — 작업 중 겹치기 쉬운 파일과 오류 해결법

## 작업 시작 순서
1. 본 리포를 **포크**해서 내려받는다. 처음 한 번만 본 리포를 `upstream`으로 등록한다.
   ```bash
   git remote add upstream https://github.com/aio-03-p1-team1/table-order.git
   ```
2. **작업 시작 전**에 본 리포 `dev`를 내 포크 `main`에 맞춘다.
   ```bash
   git fetch upstream && git pull --rebase upstream dev
   ```
3. **0번 항목(개발 흐름 확인)** 을 가장 먼저 한다. 자기 `docs/todo/TODO_본인이름.md`의 0번이다. 개발 전용 테스트 버튼(`DEV_TEST_BUTTON=1`)으로 `test` 테이블에 값을 넣고 `1`이 나오는지 확인하는 연습이며, 이 PR은 **머지하지 않고 닫는다**.
4. 내 TODO 항목을 하나 골라 구현한다.

## 개발 방법
- **내 포크 `main`에서 계속 개발**한다. 작업용 브랜치를 따로 만들지 않는다.
- PR은 포크 `main`에서 본 리포 **`dev`로만** 보낸다. 본 리포 `main`에는 직접 PR·push 하지 않는다. `main`은 SEONGHO가 `dev`를 확인한 뒤 머지한다.
- **한 PR에는 TODO 항목 하나만** 담는다. 한 항목을 끝내면 PR을 보내고, **머지된 뒤 `dev`를 다시 받아서**(위 2번) 다음 항목을 시작한다.
- 수정 파일은 최소로, 기존 코드는 최대한 유지한다. 새로 추가한 코드에는 초급 개발자도 이해할 수 있게 한국어 주석(무엇을·왜)을 단다.
- `.env`와 비밀 키(`SOLAPI_*`, `SUPABASE_SERVICE_ROLE_KEY`, `JWT_SECRET`, `ADMIN_TOKEN`)는 커밋하거나 화면·로그에 노출하지 않는다.

## 실행 (자세한 명령은 `AGENTS.md`)
- 서버: `cd backend && cp .env.example .env && uv sync && uv run fastapi dev main.py`
- 화면(저장소 루트): `streamlit run user/app.py --server.port 8501` (손님, `?table=12`로 테이블 지정), `streamlit run admin/app.py --server.port 8502` (관리자)
- `backend/.env`의 **`APP_ENV=dev`** 이면 손님 화면은 모의 회원으로 **자동 로그인**하고, 관리자 화면은 토큰 입력을 생략한다. dev가 아니면 우회가 없다. 관리자 토큰 입력을 켜려면 `ADMIN_SKIP_TOKEN=0`으로 두고 `ADMIN_TOKEN`을 쓴다.

## PR 보내기 전에
- `cd backend && uv run pytest -q` 와 저장소 루트의 `python -m pytest tests -q`가 **둘 다 통과**해야 한다. 실패하면 PR을 보내지 말고 먼저 고치거나 보고한다.
- 테스트를 skip하거나 지워서 통과시키지 않는다. 더미를 실제 구현으로 바꿀 때만 해당 테스트의 `skip`을 제거한다.
- 끝낸 항목은 내 `docs/todo/TODO_*.md`에서 `- [x]`로 체크하고 맨 위 진행 순서 표의 상태도 고쳐서 **같은 PR**에 넣는다. 테스트까지 통과한 항목만 체크한다.
- PR 직전에 `dev`를 한 번 더 받아서 충돌을 줄인다.

## 커밋·PR 형식
- 커밋 첫 줄: `종류: 한글 요약` (종류는 `feat`·`fix`·`docs`·`refactor`·`chore`·`test`). 마침표 없이 "~추가", "~수정"처럼 끝낸다. 빈 줄 다음 본문에 **무엇을·왜** 바꿨는지, TODO 번호와 함께 적는다.
- PR 제목: `종류: 한글 요약 (TODO_담당 항목번호)` 예) `feat: 룰렛 하루 1회 제한 (TODO_수용 3-2)`
- PR 본문: **변경 내용 / 테스트 방법 / 테스트 결과 / 미해결 문제**(없으면 "없음") 네 가지를 반드시 적는다. 예시는 `AGENTS.md`.
